# NetExpert — Phase 4G Real Security Integration Report

**تاريخ التنفيذ:** 2026-11-02، **الفرع:** `codex/security-phase-4`، **HEAD:** `a5d50696fbe24a83f8fa57034b3ea1998858167e`.

## ملخص التنفيذ

أُجريت الاختبارات على Supabase محلي فقط. بقيت تعديلات 4E و4F غير المحفوظة في الفرع كما هي؛ لم يحدث دفع أو دمج أو نشر أو اتصال بقاعدة الإنتاج. تستخرج أداة الاختبار مفاتيح Supabase المحلية في الذاكرة، وتتحقق من عنوان loopback والمنفذ قبل استخدامها، ولا تطبع المفاتيح. أُنشئت شركات وحسابات وهمية بأدوار Admin وManager وOperator وViewer وجلسات Supabase Auth فعلية. جرى تشغيل قاعدة ثانية مستقلة من الصفر، مع الاحتفاظ بالقاعدة السابقة.

أكدت الجلسات الحقيقية ثلاث مشكلات صلاحيات/اتساق، ومشكلة في تثبيت العقود من الصفر. أصلحتها Migrations محلية قابلة للمراجعة وأُعيدت الاختبارات بعد الإصلاح. لا يُعد ذلك موافقة على تطبيقها في Staging أو الإنتاج.

## ثغرات ومشكلات ثبتت عمليًا

1. **المشتريات والبيانات المالية — مرتفعة:** سياسة `public.purchases` استخدمت `procurement` بينما اسم القسم النهائي `purchasing`، فمُنعت حتى قراءة المسؤول. سياسات `assets` و`expenses` و`purchases` من نوع `FOR ALL` خلطت صلاحية القراءة بالكتابة. قبل الإصلاح فشل اختبار جلسة حقيقية؛ بعد تطبيق `migrations/20261102_financial_policy_alignment.sql` محليًا، نجحت القراءة المصرح بها ورُفضت كتابة Viewer والعبور بين الشركات.
2. **اتساق مرفقات الملاحظات — متوسطة:** استطاع مالك الملف حذف كائن `knowledge-files` مباشرة وهو مرتبط بسجل `knowledge_attachments`، فيبقى مرجع مكسور. قبل الإصلاح أثبت الاختبار ذلك؛ بعد `migrations/20261102_knowledge_linked_object_delete_guard.sql` رُفض الحذف المباشر ونجح الحذف بعد فك الارتباط وفق مسار الواجهة الحالي.
3. **تثبيت العقود النظيف — عالية وظيفيًا:** `supabase-workspace.sql` يسحب GRANT من `contracts`؛ Migration العقود السابق أعاد RLS ولم يعد صلاحية الجدول والتسلسل، ففشل اختبار العقود في قاعدة نظيفة برسالة منع الصلاحية. أضاف `migrations/20261102_contracts_explicit_permission.sql` صلاحيات الجدول والتسلسل للمستخدم الموثق مع استمرار RLS؛ نجحت اختبارات العقود المصرح بها والممنوعة.
4. **قراءة الملاحظات المشتركة — متوسطة وظيفيًا:** احتوى `migrations/20261021_knowledge_split.sql` على `workspace_write` داخل سياسة SELECT، فتعذر على Viewer المصرح له قراءة الملاحظة المشتركة عند التثبيت النظيف. صُحح ملف التأسيس التاريخي، وأضيف `migrations/20261102_knowledge_read_permission_fix.sql` لمسار ترقية القواعد القائمة. أعيد الاختبار بنجاح.

لم تُطبّق أي من هذه التغييرات على الإنتاج. بقيت سياسة الأجهزة المشددة من المراحل السابقة، ونجح اختبار رفض كتابة Viewer المحلي.

## حدود الإثبات ومخاطر متبقية

- **GRANT drift — مانع Staging:** تعريفات 64 سياسة متطابقة، لكن 37 من 38 جدولًا تختلف صلاحياتها بين القاعدة السابقة والتثبيت النظيف. عدد فروق الأعمدة: authenticated SELECT=11، INSERT=19، UPDATE=19، DELETE=18، وanon SELECT=20. اختبار anon على جداول حساسة مزروعة لم يُرجع صفوفًا، لأن RLS منعها، لكن ذلك لا يبرر توسيع GRANT تلقائيًا. يلزم تدقيق كل جدول وتثبيت خط أساس بأقل صلاحيات ثم إعادة إنشاء قاعدة نظيفة واختبار مسار ترقية قاعدة قائمة.
- **الحساب الموقوف عالميًا — NOT TESTED:** جرى اختبار تعليق عضوية الشركة وانقطاع الوصول إليها. لم نغيّر حالة الملف الشخصي العامة لأن trigger `protect_profile_access` رفض التغيير حتى بحساب الخدمة المحلي؛ لم نتجاوز الحماية لتصنيع نتيجة.
- **قبول الدعوات — BLOCKED:** Edge Function `supabase/functions/invite-organization-user/index.ts` يحدد `redirectTo` إلى `https://www.netexpert.dev/`. لم نتبع دعوة محلية يمكن أن تنقل المتصفح إلى الإنتاج. يلزم مسار redirect تجريبي مقيد بالبيئة قبل الاختبار.
- **انتهاء الجلسة/الرمز وتحويل كلمة مرور حساب آخر — NOT TESTED بالكامل:** اختُبر رفض جلسة غير صالحة وخروج وإعادة استخدام refresh token ورابط استعادة محلي مرة واحدة، لكن لم تُختبر كل مدد الانتهاء أو جميع صور تبديل الحساب.
- **Cron تحت حمل فعلي — NOT TESTED:** اختُبر التفويض وطلبان متزامنان مع صفر مواقع مفعّلة. لم تُختبر إعادة المحاولة، الإشعارات، المهلات، وعزل الشركات أثناء معالجة مهام حقيقية. لم تُطبّق جدولة `pg_cron` في البيئة النظيفة لغياب الامتداد.
- **تغطية RLS/RPC/API — جزئية:** الاختبارات تشمل الجداول والمسارات المذكورة أعلاه مع جلسات حقيقية، لكنها ليست مصفوفة كاملة لكل RPC وكل endpoint وكل حالة عمود. مراجعة `SECURITY DEFINER` واختبار تعديل عضوية غير مصرح به ورفض تنفيذ anon لـ cron موجودة، لكن لا يمكن استنتاج سلامة جميع الدوال منها.
- **ESLint:** 17 تحذيرًا في Hooks والصور. لم تُجرَ تغييرات سلوكية بلا دليل؛ تُراجع التأثيرات المرتبطة بطلبات البيانات في مهمة مستقلة.

## الاعتماديات

نتيجة `pnpm audit --json`: **3 متوسطة، 0 عالية، 0 حرجة**. `@tiptap/core` يظهر في مسارات مباشرة ومتعدية بإصداري 2.27.2 و2.27.3؛ الإصلاح المعلن يتطلب سلسلة 3.x، لذا لا تُرقّى core منفردة عن إضافاتها دون اختبار محرر الملاحظات. `postcss-selector-parser` متعدية في أدوات البناء؛ يلزم تحديث محدود متوافق بعد تثبيت مسار الاعتماد. `minimatch` متعدية عبر `exceljs/archiver` وأدوات ESLint، والنسخة المعالجة المعلنة 11.0.1؛ لا نفرض Major عامًا على شجرة الاعتماديات. لم يُستخدم `audit --fix` ولم تُحدث حزمة عشوائيًا. المعالجة المتبقية تتطلب اختبار توافق مستهدف.
